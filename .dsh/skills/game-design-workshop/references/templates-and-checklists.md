# 游戏设计实战模板与检查清单 (Templates & Checklists)

> **来源与适用范围**：本页是书籍方法论、公开行业实践与仓库自定义启发式规则的二次整理；具体阈值必须结合品类、引擎和玩家测试校准。详见 [来源与校准规范](../../SOURCE_PROVENANCE.md)。


本文件汇集了《游戏设计梦工厂》（Game Design Workshop）实操流程中最核心的 7 大模板与评估清单。

---

## 模板 1：游戏单页概念案 (One-Page Pitch Template)

用于在立项初期极速梳理核心构想、对齐团队认知或向发行商进行极简 Pitch。

```markdown

### 2. 核心玩法循环 (Core Gameplay Loop)

1. **[卖点 1 - 机制创新]**:

3. **[卖点 3 - 社交/系统动态]**:

- **目标平台**: PC / 移动端 / 主机 / Web
- **模式**: 单人 / 多人联机 (PvP / PvE / 合作)
```

## 模板 2：以玩为中心的核心 GDD 大纲 (Playcentric GDD Outline)

```markdown
# [游戏名称] 核心设计文档 (Game Design Document)

## 1. 概述与体验愿景 (Executive Summary & Vision)
- 游戏类型 (Genre):
- 核心体验目标 (Player Experience Goals):
- 故事与戏剧前提 (Dramatic Premise):

## 2. 形式元素规范 (Formal Elements Specification)
- **玩家结构 (Players)**: 玩家数量、交互模式（合作/对抗/非对称）、角色定义。
- **目标系统 (Objectives)**: 主目标（胜利/通关条件）、次要目标（阶段任务/收集品）。
- **规程与流程 (Procedures)**: 开局设置、每回合/实时输入流程、特殊事件触发、终局结算。
- **核心规则集 (Rules)**: 动作限制、伤害判定公式、死亡/失败惩罚。
- **资源系统 (Resources)**: 资源类型表（生命、金币、精力、空间、信息）、产出与消耗链条（Sinks & Sources）。
- **冲突与阻碍 (Conflict)**: 敌人 AI 行为树、关卡陷阱阻碍、资源权衡困境。
- **边界与魔圈 (Boundaries)**: 地图空间边界、时间限制、规则适用范围。
- **终局与结算 (Outcomes)**: 计分体系、胜利/失败展示、重玩奖励。

## 3. 戏剧与叙事系统 (Dramatic Elements)
- **角色设计 (Characters)**: 主角背景与动机、NPC 互动规则、反派驱动力。
- **叙事弧线 (Dramatic Arc)**: 章节结构、关键剧情转折点（Beat Sheet）、与关卡难度的对应关系。
- **世界观与视听风格 (World & Aesthetics)**: 世界法则、视觉基调、环境叙事要点。

## 4. 核心系统动力学 (System Dynamics)
- **正反馈设计 (Positive Feedback)**: 滚雪球机制与终结手段。
- **负反馈设计 (Negative Feedback)**: 动态平衡与翻盘机会保护。

## 5. 关卡与进程 (Progression & Level Design)
- 技能解锁与心流曲线 (Flow Curve)。
- 阶段性难度与机制教学（引导 -> 练习 -> 考验 -> 变奏）。
```

## 模板 3：实体/极简原型验证清单 (Prototyping Checklist)

在制作原型和开始测试前，逐项检查：

- [ ] **核心假设明确性**: 是否写下了本轮原型要测试的具体假设（而非“看看好不好玩”）？
- [ ] **机制最小化**: 是否剥离了所有非核心机制（例如：先不要做背包系统，只验证战斗技能搭配）？
- [ ] **材料与可修改性**: 规则和数值是否能用纸笔在 10 秒内涂改调整？
- [ ] **极端情况预演 (Stress Test)**:
  - [ ] 如果玩家一直采取最保守/挂机策略会怎样？
  - [ ] 如果玩家全部资源投入单一点（偏科打法）是否会破坏游戏？
  - [ ] 是否存在任何死循环或无法结束的死锁状态？
- [ ] **单局时长控制**: 原型单局是否能在 5-15 分钟内完成快速验证？

## 模板 5：游戏机制健康度体检表 (Mechanics Diagnostic Rubric)

用于对已有策划案或机制进行结构化诊断打分（1-5 分制）：

| 评估维度 | 核心检验问题 | 评分 (1-5) | 诊断要点与改进建议 |
| :--- | :--- | :--- | :--- |
| **1. 玩家能动性 (Agency)** | 玩家的选择是否具有实质性影响，还是伪选择？ | | |
| **2. 目标清晰度 (Objective Clarity)** | 玩家在任何时刻是否都知道自己“下一步该干什么”？ | | |
| **3. 决策有意义度 (Meaningful Choice)** | 是否存在两难困境与风险收益权衡？是否存在唯一无脑最优解？ | | |
| **4. 规则完备性 (Rule Completeness)** | 边界条件、胜负判定与资源消耗是否逻辑闭环？ | | |
| **5. 反馈及时性 (Feedback Loop)** | 系统的正负反馈是否健康？落后玩家是否有悬念，领先玩家是否有爽感？ | | |
| **6. 戏剧与玩法契合度 (Ludonarrative)** | 机制的操作手感与规则是否契合故事情境与情感目标？ | | |
| **7. 学习曲线与心流 (Flow Curve)** | 挑战攀升是否平滑？是否存在突兀的难度悬崖或过长的无聊期？ | | |

## 模板 6：极简原型功能裁剪四象限矩阵 (MVP Scoping / MoSCoW Matrix)

用于在制作极简可玩灰模或纸面原型时，严格控制系统范围，防止“特性膨胀 (Feature Creep)”：

```markdown
# [原型代号] 极简功能裁剪四象限矩阵 (MVP Scoping)

| 裁剪象限 | 包含的功能/机制 | 判定理由与验证目标 |
| :--- | :--- | :--- |
| **必须包含 (Must Have)**<br>*(缺少则无法验证核心假设)* | 1. [核心物理动词/操作交互]<br>2. [基础胜负/通关判定]<br>3. [核心冲突源] | 仅保留最纯粹的玩法闭环，验证“到底好不好玩” |
| **应该包含 (Should Have)**<br>*(极大影响体验但可先用低配替代)* | 1. [占位音效/打击顿挫]<br>2. [极简 UI 血条/得分] | 维持最基本的信息可见性与手感反馈 |
| **可以暂缓 (Could Have)**<br>*(锦上添花，首轮原型坚决不做)* | 1. [复杂装备合成/分支技能树]<br>2. [过场剧情对话/多角色选择] | 避免将时间浪费在非核心外围系统上 |
| **坚决剔除 (Won't Have)**<br>*(原型阶段严禁投入精力)* | 1. [高精贴图/粒子特效]<br>2. [商业化商城/抽卡系统] | 坚守 "Fail Early, Fail Cheap" 铁律 |
```

## 模板 7：测试复盘与改动行动计划表 (Playtest Debrief & Action Sheet)

用于在每轮玩家测试结束后，结构化总结病灶并输出明确的改版行动项：

```markdown
# 玩家测试复盘与改动行动表 (Playtest Debrief # [轮次编号])

- **测试日期 / 原型版本**: 
- **受测玩家画像与样本数**: [例如：3 位 Roguelike 老玩家 + 2 位泛动作玩家]
- **核心验证假设**: [本轮测试重点验证的 1~2 个假设]

### 1. 假设验证结论 (Hypothesis Verdict)
- [假设 1]: **[成立 / 部分成立 / 被推翻]** — [简述数据与现象佐证]
- [假设 2]: **[成立 / 部分成立 / 被推翻]** — [简述数据与现象佐证]

### 2. 发现的关键病灶与分级 (Issue Registry)
| 编号 | 严重级别 (P0-P3) | 现象记录 (Symptom) | 根因归类 (形式元素/戏剧元素) |
| :--- | :--- | :--- | :--- |
| #01 | **P0 致命阻塞** | 玩家连续 3 次在第 2 阶段耗尽体力且无法回复，陷入死局 | 资源转换链缺失保底回复机制 |
| #02 | **P1 认知断层** | 80% 玩家未发现长按蓄力机制，误以为 Boss 无法破防 | 缺少受击蓄力视听觉隐性引导 |
| #03 | **P2 流程摩擦** | 战斗结算后返回大厅的等待时间长达 15 秒 | 垃圾时间过长，打断心流 |

### 3. 外科手术式改动方案 (Keep / Cut / Tune)
- **保留核心 (Keep)**: [测试中表现惊艳、玩家情绪高涨的设计点]
- **剔除冗余 (Cut)**: [增加认知负担却毫无乐趣的复杂规则]
- **调优数值与机制 (Tune)**: 
  1. [改动项 1]: 增加体力归零时的缓释机制（土狼时间 / 保底 1 点生命）。
  2. [改动项 2]: 重构第 2 阶段 Boss 蓄力光效与音效前摇。

### 4. 下一轮原型验证假设 (Next Iteration Hypothesis)
- *下一轮我们要验证*: [针对上述改动提出的新假设与标准]
```

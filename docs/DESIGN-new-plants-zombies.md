# 设计案 · 坚果墙 / 火豌豆 / 橄榄球僵尸 / 气球僵尸

> 版本：草案 **v2**（v1 基础上按用户定稿修订：坚果=免伤盾；气球可被爆炸打；新增「吃鸡式枪械槽位」章节 §6）  
> 产出：`/game-design-orchestrator` 模式 B（多专家圆桌）+ 透镜质询 + 量化计算  
> 落地坐标：所有数值进 `src/config.js`；本文档与 `docs/GAMEPLAY.md` 同步更新

## 0. 一句话

给**现有沙盒**补两条此前空缺的战术轴 —— **火力轴（更高 DPS + 持续伤害）** 与 **空间轴（一级高度：能不能打得到）**；同时把「一把随身武器」的旧模型换成**吃鸡式的少量武器槽 + 主动换枪**，让「带什么、换什么、保不保得住当前这把」成为一局里的第二个资源决策。

## 1. 先摸清现状（设计基线）

| 维度 | 现状 | 对新内容的硬约束 |
| --- | --- | --- |
| 武器 | 10 株；4 株初始（豌豆∞ / 寒冰 3 / 樱桃 22 / 玉米炮 40），6 株地面拾取（一包弹药，打空自动回豌豆） | `starter:true` 的植物**没有弹药概念**，只有 `cost` 阳光。坚果要塞进植物栏，就必须先补「弹药」这个机制 |
| 僵尸 | 4 型全部**近战地面单位**；`acc` 只有 cone/bucket/club 三种程序化配件 | 新僵尸需要新 `acc` 分支；空中单位需要一套**高度判定**，全项目目前只有水平距离 |
| **武器槽** | `WeaponSystem.carried` **只有一个 index**；捡新的会 `ammo[旧]=0` 直接清空；HUD 只有 `.loot-btn` 一个 DOM；数字键 5 / Q 切回战利品 | 这一条是本次改动里**最大的一处工程**，需要重写 `carried` 模型、HUD 槽位 DOM 与按键映射 |
| 命中 | 豌豆/仙人掌/玉米炮都是 `segmentSphereT` 扫掠两个球（胸 0.95×/0.46×，头 1.45×/0.36×），**没有遮挡测试、没有高度上限** | 只要不写高度上限，任何子弹都能打到空中的东西 → 「打不到气球」必须显式实现 |
| 伤害入口 | 三个：`ProjectileSystem.update`（弹丸直击）、`WeaponSystem.hitscan`（玉米炮/辣椒）、`ZombieManager.damageArea`（爆炸） | 新机制（护甲、空中免疫、燃烧）必须在**三处一致**，否则会出现「玉米炮能打气球、豌豆不能」的破绽 |
| 波次 | `wavePlan(n)` 纯数量函数，无保底；同屏上限 14 | 加新僵尸后，**低阶僵尸占比会从 100% 掉到约 74%**（第 20 波），必须补「无钥匙保底」 |
| 阳光 | 初始 70，每只普通僵尸掉 1 颗 = 5 阳光 | 新增阳光沉没口会直接挤压寒冰/樱桃/玉米炮 |
| 底层能力 | 无遥控/投掷/穿甲/燃烧/空中单位；僵尸不会跳；`Zombie` 只有 `hit()` 一个受击口 | 见 §2 的三条红牌 |

**结论**：这不是「加 4 个数据条目」的活 —— 有 3 项需要先扩底层概念（充能模型、空中高度、材质护甲），**另有 1 项要重构持枪模型**（吃鸡式槽位）。

## 2. 圆桌会诊（模式 B 核心结论）

### 2.1 🚨 核心病灶联合诊断

> **四条需求里有三条在问「我要更强的数值」，但游戏缺的不是数值，是「解题维度」。**  
> 火豌豆与橄榄球如果只是「更高的 DPS / 更高的血量」，会被现有平衡公式直接吸收掉，玩家体感不到任何变化。至于气球 —— 用户已定稿「爆炸类也能打死」，这恰好替我们解决了最危险的那个坑：**爆炸是初始植物就有的钥匙，气球永远不会变成不可防守的死亡事件**。真正的空缺因此落在别处：玩家手上永远只有一把战利品，而新内容把「该用哪把武器」变成了每波都要重新做的判断，单手一把已经不够用了。

### 2.2 ⚔️ 四维交叉质询

| 专家 | 对你四条需求的质询 |
| --- | --- |
| **Fullerton（梦工厂）** | 免伤盾是本作第一个**真正改写碰撞语义**的东西：僵尸打在盾上，玩家一点血都不掉。所以整个系统的重量必须压在「盾有多少血、破盾多快」上——盾太厚就是无敌点，太薄就是废纸。同时它给了一个漂亮的**负反馈**：盾破的时候玩家不是「掉 100 血」，而是「**失去了一个自己攒出来的资源**」，挫败感有实体。 |
| **宫本茂 / 樱井（任天堂）** | 火豌豆的**核心玩具动词**必须是「*燃烧*」而不是「伤害 +33%」。33% 的差异要靠读条才能感知，燃烧是**看得见的**——命中立刻溅出火星、僵尸身上冒火苗、死亡烧黑。一个点子同时解决「战斗反馈」和「对空弱点」两个问题。 |
| **Totten / Valve（关卡）** | 气球把「水平距离」这套现有 AI 整个绕过去了：`attackRange` 只算水平距离，空中单位会**贴到玩家头顶挥空**。必须补垂直判定，否则它的行为无法读取。另外空中的东西必须能被**看见**——三个高柱/楼挡住视线时，玩家的信息是断的。 |
| **Schell（透镜之书）** | 【#35 意义选择透镜】：现在是「一发子弹一把枪」——捡到顺手的就再也不想换，捡到不顺手的就只能捏着鼻子用。**武器槽位才是这一版真正的意义选择**：带 2 把还是 3 把？带一把能打空中的还是一把能破甲的？丢了还得回去捡。**【#37 隐性容错】**：气球已有 4 类钥匙（仙人掌 / 火豌豆 / 爆炸 / 高处），运气差也不会判死。**【#88 优雅度】**：护甲用「材质」表达（铁桶=金属抗豌豆、头盔=硬抗一切但怕火），规则极简但产生的变化足够多。 |

### 2.3 🛠️ 外科手术式结论

- 🟢 **Keep**：四条需求全部保留，但**每一条都要挂一个「多用途」**：
  1. 坚果 = **免伤盾**（按用户定稿）+ 充能弹药系统（让玉米炮第一次有真正的竞争关系）
  2. 火豌豆 = 高伤 **+ 燃烧（废护甲、削弱对空）**
  3. 橄榄球 = 厚甲高血快 **+ 护甲做成材质驱动（Differentiator）**
  4. 气球 = 空中单位 **+ 一级高度轴（Hybrid occlusion）**
  5. **武器槽位**（本版新增，按用户要求对齐吃鸡）：少量槽位 + 主动换枪 + 槽满替换 + 换枪耗时
- 🟢 **按用户定稿保留（v1 曾质疑，现在照办，但补了防崩的护栏）**：
  - ✅ **坚果 = 免伤盾**（玩家整个本轮伤害归零）。护栏见 §4.2「防无敌点的三条硬约束」：盾有血、破盾有明确动画、盾内玩家**不能开火时盾受双倍压力**、且罩内开火会额外消耗盾血。
  - ✅ **气球可被爆炸打死**。因为是球形距离衰减，气球离地 2.2 米，爆炸对它天然生效，无需额外规则。
- 🔴 **Cut**：
  - ❌ **删掉 v1 的「单发伤害 ≥ 30 才能打气球」阈值**。用户定稿后改为**按武器类型白名单**：`aerial: true` 的爆炸武器 + 仙人掌 + 火豌豆（弱），其余弹丸打不到。原因见 §5.2 —— 阈值会让「玉米炮恰好能打、豌豆恰好不能」变成一条玩家猜不出来的隐藏规则。
  - ❌ **不做燃烧 DoT 叠层**（最多 1 层）。多层会与 0.17s 射速相乘，DPS 爆表，且每帧遍历材质开关已逼近性能红线。
  - ❌ **不做无限武器槽**（每捡一把就永久多一格）。那会把「选武器」这个决策本身干掉，而且 6 格底部栏在 iPhone 横屏只有 19px 余量（见 §6.3）。
- 🟡 **Tune**：见 §8 的完整调参清单。

## 3. 设计目标与红线

| 目标 | 验收口径 |
| --- | --- |
| G1 新内容不做「纯数值替代」 | 每一件新东西都改变**一种打法**（守点 / 输出 / 破甲 / 对空） |
| G2 不产生单一支配策略 | 任何一件新东西都有它打不动的敌人（见 §4.4 克制矩阵） |
| G3 不产生不可防守的事件 | 气球有 ≥ 2 把钥匙；橄榄球有 ≥ 3 条反制路径 |
| G4 不打断现有 60fps | 每只新僵尸 **≤ 2 个额外 draw call**；燃烧特效复用现有 `Particles` 池 |
| G5 失败可读 | 玩家打不动时必须「听得懂」：金属火花音 + 灰字「护甲」+ 雪碧字「MENTAL(免疫)」 |

## 4. 武器设计

### 4.1 设计前提：植物栏的「弹药模型」必须升级

**这是整份设计里最重要的一个工程决定。**

- 现状：4 株初始植物只有 `cost`（每次开火的阳光消费），没有弹药。
- 坚果如果照搬现有模型，只能做成「22 阳光点一下换 8 秒盾」——那它就是个**技能**，不是植物，也放不进植物栏的语义。
- 所以引入**统一的三段式资源**（对 4 株初始植物全部适用，但**默认值保持现有行为不变**）：

```
charges  : 开火扣 1（坚果 = 盾的次数）
maxCharges: 上限（豌豆/寒冰 Infinity = 现有行为不变）
recharge : 0 时表示不自动回复（现有行为）；坚果为 6 秒回 1 片
```

> 工程上这是一个**纯增量字段**：`charges === Infinity` 时所有旧逻辑原样走通，不需要改现有 4 株的任何数值。
>
> **坚果是唯一需要弹药语义的初始植物**：`cost` 负责「按一次花 25 阳光」，`maxCharges/recharge` 负责「囤多少个、多久回一个」。资源语义因此和 PvZ 原作一致：**坚果是有冷却的种植**，不是无限技能。

### 4.2 坚果墙 · **免伤盾**（用户定稿）

> **一句话语义**：按「坚果」→ 玩家脚下长出一颗坚果把自己罩住 → 罩内**所有僵尸伤害归零** → 坚果自己按价格扣血 → 血归零、坚果碎掉、玩家重新暴露。

| 项 | 值 |
| --- | --- |
| id / 名 | `wallnut` / 坚果墙 |
| `starter` | `true`（进植物栏，第 5 格，数字键 **5**） |
| `kind` | **`shield`**（新分支：非弹丸、非部署物，是**玩家自身的状态**） |
| `cost` | **25 阳光**（≈ 5 只普通僵尸的掉落） |
| `hp` | **400**（盾血量，不是坚果实体的血） |
| `maxCharges` | **10** 颗 |
| `recharge` | **0.6 秒 / 颗** |
| `cooldown` | **1.0 秒**（两次套盾之间的最短间隔） |
| `radius` | **0.85 米**（罩住玩家的可见球壳） |
| `aerialGuard` | **false**（气球从头顶咬，护盾不挡 —— 见下） |

#### 运行语义

1. **套盾瞬间**：盾血 = 400（**直接满血，不叠加、不刷新**：盾还有血时按坚果无效，会播拒绝音）。植物栏第 5 格显示剩余盾血，罩壳球完整体现剩余血量：**由绿变黄变红，低于 25% 开始闪烁**。
2. **免伤**：罩内期间 `Player.damage()` 被 `WallNuts.absorb()` 先行拦截，僵尸的这次伤害**全部打到盾上**（不溢出），玩家 0 血损失、不触发无敌帧、不打断回血计时。
3. **破盾**：盾血归零 → 坚果碎裂（白色碎片 + 裂纹声 + 屏幕轻微抖动）× → 玩家暴露。**玩家不会因为破盾受伤**，破盾本身只给 0.35 秒的软弱无敌（防止破盾瞬间被同一波连击打穿）。
4. **主动取消**：再按一次坚果键（或数字键 5）可以**主动收盾**（保留剩余盾血？→ **不保留**，见下面「节奏护栏」）。
5. **吸引**：僵尸**优先攻击玩家本体而不是坚果**——坚果是玩家的护甲，不是诱饵。僵尸在被盾挡住攻击后仍会继续贴上来啃，所以盾是「**买时间**」而不是「**拉仇恨**」。

#### 盾血 400 到底能撑多久（这是全部平衡的支点）

| 敌人组合 | 破盾时间 |
| --- | --- |
| 1 只普通僵尸 | 71 秒（= 基本等于「不会被单只僵尸威胁」，符合预期） |
| 1 只橄榄球僵尸 | 40 秒 |
| 1 只巨人僵尸 | **24.6 秒** |
| **6 只普通僵尸贴身** | **9.3 秒** ← 真正的压力点在这一行 |
| 罩内用火豌豆持续开火 | 每枪 −1 血，**68 秒**烧完自己的盾（相当于「边打边自残」） |

> 也就是说：盾不是「一段时间内无敌」，而是「**用 25 阳光换 9~24 秒的免疫窗口**」。第 20 波开始每波几十只僵尸，这 9 秒就是玩家**唯一能站着把樱桃丢进去的时间**。

#### ⚠️ 防无敌点的三条硬约束（这节是这套机制能不能活的关键）

| # | 约束 | 为什么必须有 |
| --- | --- | --- |
| **C1 血是做出来的，不是打出来的** | 僵尸咬击间隔 1.28 秒，玩家每吃一次伤害后 0.32 秒无敌 → **实际吃伤约 0.8 次/秒**（0.32 秒会顶掉近 1/4 次）。400 血 ÷（0.8 次/s × 9 伤）= **单只普通僵尸要啃 71 秒**；6 只贴身 = **9.3 秒破盾**；Boss 单只 = 24.6 秒 | 破盾速度是**场上僵尸数量的函数**，这正是我们要的：越到后期越撑不住。玩家必须在「套盾站桩」和「攒玉米炮」之间选 |
| **C2 覆盖期不允许「白白站桩」** | 套盾期间玩家**移动速度 ×0.88**（重甲感），**开火时盾血额外 -1/发** | 否则最优解就是「套盾 → 站着不动一直打」。加上这条之后，站在盾里输出会成为**可被计算的风险**：火豌豆 0.17s 一发 = **5.9 血/秒**（400 血盾只能连续打 68 秒），机枪 13.3 血/秒，**比僵尸咬还快** |
| **C3 气球不吃盾** | `aerialGuard: false`：气球从头顶俯冲，**伤害穿透护盾** | 否则盾一开对所有敌人都无敌，会让气球这个新机制直接作废。也正好让 §5.2 的高度轴和 §6 的槽位系统产生联动 |

> **改动前的红线提醒**：`Player.damage()` 里有 `invuln = 0.32` 和 `sinceDamage` 回血计时。盾拦截必须**放在 `damage()` 之内、invuln 判定之后**，并且**不重置 `sinceDamage`**——否则「被打」和「没被打」在数值上无法区分，回血会永远断掉。

**它改变的打法**：从「永远后退风筝」变成「**在走廊/门口买一块能站着打的立足点**」。价钱 25 阳光 / 400 血 / 限制移速 88% / 气球不防 —— 这是一笔**有明确边界的交易**，而不是一个「打开就赢」的开关。

### 4.3 火豌豆射手 · 定位「高输出 + 燃烧」

| 项 | 值 | 对比豌豆 |
| --- | --- | --- |
| id / 名 | `firepea` / 火豌豆射手 | 植物栏第 6 格，数字键 **6** |
| `starter` | `true` | 阳光植物 |
| `cost` | **2 阳光/发** | 豌豆 0 |
| `cooldown` | **0.17 秒** | 0.15 |
| `damage` | **20** | 15 |
| `kind` | `pea`（复用现有弹道） | — |
| `speed` | **78 m/s** | 74 |
| `burn` | `{ dps: 8, time: 3 }` | — |
| `armorBreak` | `2`（护甲伤害倍率） | 1 |
| `aerial` | **`'weak'`**（可打气球，伤害 ×0.25） | `false`（打不到） |
| `color` | `0xff7a1a` | 0x8ade2a |

- **理论 DPS：117.6**（豌豆 100，+17.6%）。看起来不多，但**燃烧单独贡献 8 DPS**，实际对单体是 125.6。
- **视觉（这条比数值重要）**：弹丸是**带尾巴的火球**（`Particles` 每帧在弹丸位置吐 1 颗火星，复用现有粒子池，不新增 draw call）；命中的瞬间喷一圈橙红火星 + 点一盏**短暂的点光源**（复用 `Particles` 已有的"临时点光源"能力）。
- **阳光账**：0.17s 一发 × 2 阳光 = **11.8 阳光/秒**，和寒冰的 11.5 差不多。它不是免费武器，是**要杀的武器**。
- **它改变的打法**：寒冰是「拖时间」，火豌豆是「抢时间」。两者不能同时用（共享冷却器），所以每一波都要选一次。

| --- | --- | --- | --- | --- | --- | --- |
| 豌豆（∞） | ✓ | ✓ | △ | ✓ | **✗ 4.7 秒，打不动** | ✗ 打不到 |
| 寒冰（3） | ✓ | ✓ | △ | ✓★控 | ✗ 5.4 秒，打不动 | ✗ 打不到 |
| 樱桃（22） | ✓ | ✓ | ✓ | ✓ | △ | **✓✓ 1 发必杀**（中心 210 vs 48 血） |
| 玉米炮（40） | ✓ | ✓ | ✓ | ✓ | ✓ | **✓✓ 1 发必杀**（165 vs 48 血） |
| **火豌豆（2）** | ✓✓ | ✓✓ | ✓✓ | ✓ | **✓✓ 破甲** | △ 慢：48 血 ÷ 5 伤 ≈ 10 发 / 1.7 秒 |
| 仙人掌（拾取） | ✓ | ✓ | △ | ✓ | △（穿透但没伤害） | **✓✓ 主钥匙**：30 伤 2 发 / 0.84 秒 |
| 西瓜 / 辣椒（拾取） | ✓ | ✓ | ✓ | ✓ | ✓ | **✓✓ 1 发必杀** |
| **坚果（25，免伤盾）** | 免伤·单只 71 秒 | 免伤·单只 71 秒 | 免伤·单只 43 秒 | 免伤·单只 25 秒 | 免伤·单只 40 秒 | **✗ 穿透**（`aerialGuard:false`） |

> ✓✓ = 明显优势，✓ = 正常，△ = 吃力，✗ = 无效/打不到，★ = 特殊效果  
> 注：**坚果（免伤盾）不是输出手段**，它的这一行读法是「守住 / 守多久」，不是「打得多快」。气球的解法有 4 条互不重复的路径：花阳光的爆炸、捡来的仙人掌、便宜但慢的火豌豆、以及零成本的站高处/跳起躲。

## 5. 僵尸设计

### 5.1 新机制 A：**材质护甲层**（为橄榄球服务）

不做「血条加长」，做**分层防御**。`Zombies` 配置新增：

```
armor: { material: 'buffalo' | 'metal' | 'plastic' | null, hp: <护甲值> }
```

| 材质 | 是什么 | 规则 | 谁来破 |
| --- | --- | --- | --- |
| `plastic` | 路障锥 / 塑料头盔 | 护甲 +50% 耐久，对**燃烧免疫** | 任何弹丸（1 点弹伤 -1 点护甲，耐久按 ×1.5 换算） |
| `metal` | 铁桶 | 吸收 **70%** 伤害，**对燃烧免疫**，**不吃穿透**（仙人掌穿过它不掉血） | 玉米炮、樱桃、西瓜、辣椒（爆炸无视材质） |
| `buffalo` | 橄榄球头盔 / 护肩 | 吸收 **50%** 伤害，**怕火（火伤 ×4）**，**可被燃烧焚烧**（燃烧期间 armor 每跳 -5，1.5 秒内烧光 140 点护甲） | **火豌豆**（唯一进入护甲层的弹丸）、爆炸、燃烧 |

**关键设计**：护甲被打破的瞬间播 **"啪" 的碎裂音 + 白色碎片粒子**，头盔/铁桶**从模型上掉下来**（`acc` 网格 `.visible = false`）。这一下是整场战斗的**情绪节拍**——玩家第一次「看见自己破防了」。

> 为什么是「材质」而不是「护甲值」：
> - 【#88 优雅度】一条 `material` 字段就把「铁桶为什么不怕豌豆、为什么怕玉米炮、橄榄球为什么怕火」全部解释了，不需要给每把武器写例外。
> - 玩家可以**从视觉上判断该换什么武器**（铁桶会反光=金属=别用豌豆；头盔是塑料=烧）

### 5.2 新机制 B：**一级高度（Air）**（为气球服务）

游戏里目前所有东西都在 `y = 0` 的地面上。引入**空中 2.2 米**这个层级：

```
气球僵尸：飞行高度 2.2 米（脚底离地）
```

#### 四条判定规则（三处伤害入口必须一致）

| 规则 | 实现口径 |
| --- | --- |
| **R1 只有「钥匙武器」能打到空中目标** | `ProjectileSystem` 扫掠时，若目标 `airborne` 且当前弹丸的 `aerial` 为 falsy → **跳过该目标**（子弹穿过去，在地面打出点点）。`aerial` 是武器配置里的一个字段，不是伤害阈值 |
| **R2 爆炸类全部有效（用户定稿）** | `damageArea` 改用 **3D 球距离**：`d = hypot(dx, dz, dy - 0.9)`。气球脚底 2.2 → 其对地爆心的距离约 1.3 米，**远小于最小爆炸半径 4.2 米**，所以**玉米炮 / 樱桃 / 西瓜 / 辣椒 全部 1 发必杀**（165~280 伤害 vs 48 血），且无衰减 |
| **R3 站在高处也能打到** | 玩家站在 ≥ 1.5 米平台上、且水平距离 ≤ 3 米时，**所有武器**都能命中气球（正对着打，不需要钥匙）。让雪地矮墙、沙城高台第一次有了战术意义 |
| **R4 垂直攻击距离** | 气球要咬到玩家必须满足 `|player.y − 2.2| ≤ 1.6`。玩家跳起来（最高 +1.04 米）会**躲开气球的撕咬**——这是它唯一的弱点窗口 |

#### 「高空武器」白名单（`aerial` 字段）

| 武器 | `aerial` | 实际效果 |
| --- | --- | --- |
| 玉米炮 / 樱桃 / 西瓜 / 辣椒 | `'explosion'` | **1 发必杀**（爆炸半径必须 ≥ 1.5 米，全都满足） |
| 仙人掌 | `1.0` | **2 发 / 0.84 秒**（30 伤 × 2） |
| 火豌豆 | `0.25` | 慢：48 ÷ 5 ≈ **10 发 / 1.7 秒**，且花 20 阳光 |
| 豌豆 / 寒冰 / 双发 / 三线 / 机枪 | `false`（不配） | **完全打不到** |

> **为什么改成白名单而不是 v1 的「伤害 ≥ 30 阈值」**：
> 阈值是**一条玩家猜不出来的隐藏规则**——「为什么玉米炮 165 能打、豌豆 15 不能打」是显然的，但「为什么辣椒能打到天上的东西」需要解释。白名单的规则是**一句话：「打不到天上的，只有爆炸、仙人掌、火豌豆和站在高处」。**  而且它天然匹配玩家的直觉：**爆炸是球形范围，天上地下都炸得到**。

#### ⚠️ 白名单带来的新风险与对策

| 风险 | 对策 |
| --- | --- |
| 玉米炮/樱桃是**初始植物**，气球几乎无威胁 → 新僵尸变成送分怪 | 气球**48 血 + 2.2 m/s + 2 颗阳光掉落**，价值定位是「**逼你花弹药**」而不是「杀你」：一只气球让玩家花 40 阳光（玉米炮）或 22（樱桃）。第 8 波起每波 2 只气球 = **每波固定 40~80 阳光的沉没口**，直接压缩了寒冰与橄榄球对策的预算 |
| 仙人掌的「主钥匙」定位被削弱 | 仙人掌仍是**唯一免费/无冷却开销**的空中解法（40 发弹药、0.42s、2 发一只）。它是「**不用花阳光的那把钥匙**」，仍值得专门去捡 |
| 玩家没有钥匙、也不舍得花阳光 | 规则 R3（站高处）与 R4（跳起来躲）给了零成本解法；且气球同屏有**配额上限**（§7.3），永远不会铺满 |

**气球真正的设计价值**：它不是一个「更强的敌人」，而是一个**「从阳光账户里抽税」的敌人**。这恰好与坚果（25 阳光一次）形成一进一出的经济张力——你每一波能攒下来的阳光，被气球吃掉一部分，被坚果吃掉一部分，剩下的才能给寒冰。

> **改动前的红线提醒**：R1 必须在**三处**一致实现 —— `ProjectileSystem`（弹丸）、`WeaponSystem.hitscan`（辣椒/玉米炮的直击判定 + `findAimTarget` 的辅助瞄准）以及 `ZombieManager.damageArea`（爆炸）。**只要漏一处，就会出现「玉米炮能打、豌豆也能」的破绽**。

### 5.3 橄榄球僵尸 · 「高压前排」

| 属性 | 值 | 对比（铁桶） |
| --- | --- | --- |
| `hp` | **190** | 270 |
| `armor` | `{ material: 'buffalo', hp: 140 }` | — |
| `speed` | **2.60 m/s** | 1.55（**快 68%**，是全场第二快） |

**威胁曲线**：速度 2.6 vs 玩家 5.4，从 20 米外压过来只要 7 秒。它的作用是**把玩家从掩体后逼出来**——所以它和坚果构成直接对位（坚果挡住它 3 秒，刚好够火豌豆烧完护甲）。

**造型（`Zombie.buildHat` 新增 `helmet` 分支，模型单位）**
- 橄榄球头盔：球壳（`SphereGeometry` 半开）+ 前额横杠（`TorusGeometry` 抹平）+ 面罩格栅（3 根细圆柱），深红 `0x9c2f2b` + 米白横杠
- 护肩：两侧略宽出躯干的胶囊/球体，同色
- 打破后：整套 `.visible = false`，下方露出原僵尸的头

## 6. 武器槽位系统（吃鸡式 · 新增）

> 用户的定调：**参考现在吃鸡游戏的持枪设计**。现状是「一把随身战利品，捡新的就把旧的清空」——这让玩家没有选择权，也只能在两个方案里二选一。

### 6.1 吃鸡游戏是怎么做的（参照基线）

| 游戏 | 持枪结构 | 关键设计动作 |
| --- | --- | --- |
| **PUBG / 和平精英** | **主武器 2 + 副武器（手枪）1 + 近战 1 + 投掷 4**；主武器各带弹匣 | 槽位**分类固定**，同类只能占同类槽；换枪有抬枪动作；**丢弃要主动操作** |
| **CODM** | 主 2 + 副 1 + 近战 1 + 战术 3 | 同上，副武器通常只作为「主武器没子弹时的保险」 |
| **Apex Legends** | **2 个武器槽，地位完全平等** + 手雷 | 只有 2 格，所以「带哪两把」是**每一局的核心决策** |

本作只有 10 株植物、7 件可拾取、且**没有换弹/弹匣**（`WEAPONS` 里没有 `magazine` 字段）。所以我不照抄「分类槽」（主/副/近战），而是照抄 **Apex 的「2~3 格 + 平等地位」**，这一点和第 6 条需求（火豌豆是初始植物）天然吻合：

### 6.2 本作的槽位方案

```
┌─────────────────────────────────────────────┐
│  植物栏（初始植物，阳光武器，永久持有）       │
│  [1]豌豆 [2]寒冰 [3]樱桃 [4]玉米炮 [5]坚果 [6]火豌豆 │
├─────────────────────────────────────────────┤
│  武器槽（拾取战利品，弹药制，最多 3 格）       │
│  [7]槽A  [8]槽B  [9]槽C      ← 不固定，捡到就进当前空格 │
└─────────────────────────────────────────────┘
```

| 规则 | 值 | 说明 |
| --- | --- | --- |
| 槽位数 | **3** | 参考 Apex 的「少即是决策」；3 格刚好够「一把对空 + 一把破甲 + 一把清群」 |
| 进槽方式 | 走到发光植物上 → **自动进一个空槽**并立即切换 | 保留现有的「踩上去就捡」手感 |
| 槽满时 | **不自动替换**，改为**替换提示**：底部弹出「替换哪一格？」——按 **7/8/9** 选择要替换的槽，**2.5 秒不选则取消**（拾取物留在地上） | 关键：不允许无提示地吞掉玩家正在用的武器（v0 的行为） |
| 每槽独立弹药 | 各自 `ammo`，互不影响 | 现有 `this.ammo[]` 数组已经是按武器 index 存的，天然支持 |
| 主动丢弃 | **长按槽位 0.5 秒**或按 **Backspace/G** 丢弃当前槽 | 吃鸡的必备动作；丢下的武器**回到地面**（不消失，可以回去捡） |
| 换枪 | 数字键 **7/8/9**、点击槽位、**Q 键循环** | 换枪有 **0.35 秒**抬枪动画，但**不重置开火冷却**（避免换枪躲冷却） |
| 打空 | 该槽**变灰但保留**，玩家可丢可留 | 保留空槽 = 保留「按 7 就回到手枪」的位置记忆 |

### 6.3 ⚠️ 这一改动最大的风险：和「7 格植物栏」冲突

| 版本 | 屏幕上的格子数 | iPhone 横屏 844px 可用宽度 | 结论 |
| --- | --- | --- | --- |
| 现状 | 6（4 初始 + 1 战利品 + 1 空） | ≈ 367px | ✅ 放得下 |
| 只加坚果+火豌豆（6 初始 + 1 战利品） | 7 | 7 × 58 = **406px** | ❌ **溢出** |
| **本方案（6 初始 + 3 槽）** | **9** | **522px** | ❌❌ **必然放不下** |

**所以武器槽不能平铺在底部**。方案：

```
底部一行：初始植物 6 格（数字键 1-6）—— 与目标核心操作并列，始终可见
右侧竖列：武器槽 3 格（数字键 7/8/9）—— 贴在开火按钮左上方，竖排
```

- 桌面/平板：竖列贴右侧，高度 3 × 46 + 间距 ≈ 158px，不挤占视野。
- iPhone 横屏：竖列改为**开火上方的横排 3 小格**（每格 40px），总宽 132px，放在 `weapon-dock` 之上。
- **底部一行因此维持 6 格**，也就是 `--weapon-w` 的现有计算式**完全不动**（这是本方案能在 844px 上活下来的唯一原因）。

### 6.4 为什么要 3 格而不是 2 格或无限

| 方案 | 问题 |
| --- | --- |
| **1 格**（现状） | 没有选择：捡到就是唯一，玩家只能被动接受 |
| **2 格** | 刚好卡在「对空 + 破甲」二选一，装不下第三把清群武器（西瓜/辣椒），打 Boss 时会很难受 |
| **3 格 ✅** | 「对空（仙人掌/爆炸）+ 破甲（火豌豆其实是初始）+ 清群（西瓜/辣椒）」刚好三种角色，且逼玩家在 `X` 和 `Y` 之间做**明确取舍** |
| 无限 | 槽位越多，「选」这个动作越少；且 6+7=13 格在手机上完全不可能 |

> 【#35 意义选择】落点就在这里：**3 格 = 3 个"我想带什么"的决定**，而每个决定都要用一局的时间来验证。

### 6.5 对现有代码的影响（`WeaponSystem`）

| 现有字段 | 改成 | 影响 |
| --- | --- | --- |
| `carried`（单个 index，-1 表示没有） | **`slots: [-1, -1, -1]`** + `active` 当前激活槽 | `pickup()`、`dropLoot()`、`equip()`、`reset()` 全部要改；`HUD.setLoot()` 要改成 `setSlots()` |
| `pendingDrop`（弹药耗尽后 0.45s 自动回豌豆） | **保留但改成"留在空槽"**：打空后 0.45 秒自动切回上一把初始植物，**该槽变灰不清空** | 行为对玩家更友好，也省掉「打空即消失」的意外感 |
| `hud.lootBtn`（单个 DOM） | **3 个槽位 DOM** | `HUD.buildDock()` 要重写这部分；`ICONS` 不变 |
| `Controls` 数字键 1-4 / 5=战利品 | **1-6 = 初始植物，7-9 = 武器槽，Q = 循环槽位** | `Controls.js` 的 `weaponRequest` 从 `number` 改成 `{kind:'starter'|'slot', index}` 或直接复用为 0~8 的全局 index |

### 7.3 ⚠️ 气球同屏配额（仍然必做，但理由变了）

v1 里这条是为了「玩家没捡到仙人掌就必死」。用户定稿「爆炸类能打气球」之后，**初始的玉米炮与樱桃就是天然钥匙，不会再出现死局**。但配额仍然保留，理由改成两条：

1. **阳光经济**：气球是「抽税型敌人」，每只让玩家花 22~40 阳光。如果一波里堆 5 只，就是 110~200 阳光的强制支出 —— 相当于一整波都打不出玉米炮以外的任何东西。**同屏 2 只是舒服的税负**（每波约 44~80 阳光）。
2. **帧率与认知负荷**：同屏 14 只里如果有 5 只都是空中单位，玩家要同时追踪的高度信息会超过可读范围。

**规则**：`ZombieManager.spawnOne` 里，气球 **最多占同屏上限的 20%**（14 只时 = 2 只）；超出的留在队列里等死亡再刷。

> 为什么不是「保证刷仙人掌」？拾取点位是随机的，锁死点位会让地图变无聊。**限制同屏数量**是更便宜、更不侵入的做法。

**数值校验**：气球占比 20% 时，刷怪间隔约 1.35 秒，平均每 **6.7 秒**出现 1 只气球；玩家有充足时间判断高度、决定是花 40 阳光打掉还是跳起来躲。

## 12. 验收与待验证假设

### 12.1 手感验收（人工，1440×860 + iPhone 横屏）

**坚果免伤盾**
1. 数字键 5 套盾 → 身体周围出现半透明坚果壳 → 僵尸贴脸打，**血量条纹丝不动**
2. 盾血条从绿 → 黄 → 红闪烁 → 归零时**碎裂 + 白闪 + 轻震**，玩家掉血立即恢复
3. 盾还有血时再按 5 → 拒绝音（不叠加、不刷新）
4. 罩内移速明显变慢（×0.88）；连射时盾血条**肉眼可见地掉**
5. 气球从头顶俯冲 → **穿透护盾**，玩家掉血

**火豌豆**
6. 数字键 6 切火豌豆 → 弹丸拖火星，屏内多一盏短暂的橙光 → 命中僵尸身上冒火苗 → 打橄榄球 **2.8 秒**死，打铁桶比豌豆明显快

**气球**
7. 豌豆打气球 → 子弹**穿过去**（地面打出点点）+ 金属擦过音 + 准星短暂变灰
8. 换玉米炮/樱桃/仙人掌 → **1~2 发必杀**
9. 跳起来 → 气球俯冲撕咬落空
10. 站上雪地矮墙（0.92m）+ 水平 3 米内 → 豌豆也能打到

**槽位（P2）**
11. 连续捡 3 把不同植物 → 三格依次填满
12. 捡第 4 把 → 弹出「替换哪一格？」→ 按 7 → 第 1 格被替换，**另两把的弹药不丢**
13. 2.5 秒不选 → 拾取物留在原地
14. 长按槽位 0.5 秒 → 武器掉回地面，可以走回去捡
15. 打空一个槽 → 自动切回上一把，**该槽变灰但仍在原地**

### 12.2 尚待原型验证的假设

| # | 假设 | 怎么验 |
| --- | --- | --- |
| **H1** | **坚果免伤盾不会变成「开着盾站桩打」的支配策略**（风险最高的一条） | 统计每局盾的开盾时长占战斗时长比，目标 **< 35%**；>50% 说明 C2 的「开火扣盾」不够狠，需要把 `COST_PER_SHOT` 从 1 调到 2 |

### 12.3 天然平衡

黄金制衡点：**坚果（25 阳光）+ 气球税（每只 22~40 阳光）+ 火豌豆（11.8 阳光/秒）** 三者抢同一个阳光池，而初始 70 阳光只够买 **2 颗坚果**或 **一发玉米炮 + 一发樱桃**。这种「三选二」的紧张感是本版的核心体验目标，也是 H1/H4 要验证的东西。

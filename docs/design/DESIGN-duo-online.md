# 双人联机玩法设计 ·《后院双人档》

> 状态：设计稿 v3.5（M0/M1 + 邀请链接 + M2 input/僵尸/命中/共享阳光 + 倒地救援已实现；共享补给/阳光球/结算页/resync 未实现，2026-10-30）  
> 范围：2 人、无手动房间、自动配对、自建 Linux 服务器；单人模式保留  
> 一句话：**两个人守同一波尸潮，救同一个队友，抢同一份战功。**

---

## 0. 前提与假设

| 项 | 取值 | 说明 |
| --- | --- | --- |
| 人数 | 每场固定 2 人 | 服务器可同时承载多场（默认上限 8 场 / 16 人） |
| 配对 | 全自动 | 无手动建房、无邀请码：进双人模式时若有人等待就加入，没人等待就新建一场并等待 |
| 模式 | 单人 / 双人 | 单人完全离线；只有双人才建立 WebSocket、加载网络模块 |
| 服务器 | 1 台公网 Linux VPS | Node 单进程同时托管静态资源与 WebSocket，Caddy 终止 TLS |
| 客户端 | 现有网页 | 手机 / iPad / 桌面均可；双端版本必须一致（构建号握手校验） |
| 权威 | 房主权威 + 服务器记账 | 详见 §9；这是"简单起见"的关键取舍，不是最终形态 |
| 语音 | 不做 | 用微信 / Discord；游戏内只做一键标记 |

**核心设计难题**：合作要求"你得靠我"，竞争要求"我得比你强"。两者一旦落在同一个资源上（比如阳光），就会变成互相拖后腿。  
**解法**：阳光完全共享（合作），竞争只发生在**个人战功**与**全队唯一的地面补给**上。补给不加分，抢的是火力，不是队友的命。

## 1. 体验目标

1. **并肩**：一个人打不过这一波，两个人可以。队友倒下时，你必须做出去救还是继续输出的选择。
2. **抢分**：全程没有友伤、没有推挤；补给可以抢，但抢不到也有豌豆保底。计分板一直在跳，最后一屏一定要能吵起来。
3. **有始有终**：一局 10~25 分钟，有开局等待、波次起伏、空投争夺、Boss 高潮、结算复盘与"再来一局"。

### 一句话验证假设（M2 结束前必须成立）

> 两个人在同一局里，第一波清完后会**主动**说出"我刚才比你多杀了 3 只 / 我救了你一次"，而不是各打各的。

如果这句话没出现，说明竞争层不成立，停下来改计分，不要往下做救援和空投。

## 2. 八大形式元素

| 元素 | 设计 |
| --- | --- |
| **玩家** | 2 名戴夫，能力完全相同；可选"专精"（后续版本，默认不开） |
| **目标** | 团队：守住尽可能多的波次；个人：在同一局里比队友分高 |
| **规则** | 无友伤、无玩家碰撞、共享阳光、补给先到先得、倒地可救、两人同时倒地即团灭 |
| **资源** | 共享阳光池（续弹 / 护盾 / 空投）、全队唯一的地面补给（先到先得）、个人武器槽、个人战功 |
| **冲突** | 僵尸波次（对局）、悬赏怪、地面补给与空投（两人之间的争夺） |
| **边界** | 3 张现有地图，同图同种子，双人出生点相距 3~4 米 |
| **结果** | 团队波次 + 个人分数对比（胜/负/平），写入服务器战绩 |
| **流程** | 菜单（单人 / 双人）→ 自动配对 / 等待 → 倒计时 → 波次循环 → 结算 → 再来一局 |

## 3. 核心循环与两条账本

```
 击杀掉落阳光球 ──► 共享阳光池（合作）──► 续弹 / 护盾 / 空投
                     └─ 拾取者 +5 个人分/球（只记分，不扣池）

 地面补给（全队唯一）──► 先到先得 ──► 只抢火力，不加分

 击杀 / 爆头 / 悬赏 / 救援 / 空投 ──► 个人战功（竞争）──► 局末对决 ──► 服务器战绩
```

- **阳光是团队的**：谁捡都一样进池子，所以抢阳光不会伤害队友，只会让自己多拿 5 分。
- **常规补给是全队唯一的**：先到先得，但不加个人分——抢的是火力，不是比分；空投才是 +200 的高光争夺。
- **分数是个人的**：伤害占比决定分成，救了人、抢了空投都能加分。
- **花钱是公开的**：结算页列出双方"消耗阳光"，让"谁把池子打空了"有据可查，而不是靠猜。

### 一局的标准节奏

```
自动配对/等待 → 3-2-1 → 第1波 → 清波5s → 第2波 → 清波5s → 第3波(空投)
      → … → 第5波(Boss) → 第6波(空投) → … → 两人同时倒地 → 结算 → 再来
```

## 4. 合作层（4 个机制，全部给死数值）

### 4.1 倒地与救援 —— 合作的核心动词

| 参数 | 值 | 说明 |
| --- | --- | --- |
| 倒地触发 | HP 归零 | 不结束对局，进入 `downed` |
| 倒地可爬行速度 | 1.2 m/s | 能找掩体，不能开枪 / 切枪 / 投掷 / 拾取 |
| 倒地视角高度 | 0.55 m | 镜头压低 + 红色暗角 + 心跳音 |
| 流血倒计时 | 30 s | 队友 HUD 与屏幕边缘箭头同步显示 |
| 救援距离 | 3.0 m | 超过 3.5 m 进度清零 |
| 救援耗时 | 2.5 s | 按住 E / 触屏"救援"按钮；中途受伤不打断，移动超过 0.6 m 打断 |
| 救起后 | 50% HP + 3 s 无敌 | 1.5 s 起身硬直，不能开枪 |
| 救人得分 | +150 个人分 | 救的人拿，被救的人不扣分 |
| 淘汰 | 流血结束 | 进入观战，**60 秒后或下一波清完（先到者）以 50% HP 归队**，连杀倍率清零 |
| 团灭 | 两人同时处于倒地/淘汰 | 本局结束 |

**为什么这样设计**：倒地不是惩罚，是"把队友拉回来"的 30 秒窗口。救援要花 2.5 秒、要离开输出位、还可能被一起打倒——这就是合作与竞争的交点：**救他，你会少拿分；不救，这局可能就没了。**

僵尸对倒地者的仇恨在 2.5 秒后转移给站着的人，避免"守着尸体无限补刀"导致救不起来。

### 4.2 协同集火（Coop Mark）

- 同一只僵尸在 **2.0 秒**内被两人都打过 → 该僵尸获得"协同"标记（头顶小图标），此后两人对它的伤害 **×1.08**。
- 不叠加，不要求两人靠近，只要求打同一只。
- 目的：给"集火"一个正反馈，同时天然制造"这只让我打"的争抢（因为伤害占比就是分）。

### 4.3 共享阳光池

| 参数 | 单人 | 双人 |
| --- | --- | --- |
| 初始阳光 | 60 | **80** |
| 上限 | 300 | **400** |
| 天降阳光间隔 | 30 s | **22 s** |
| 击杀掉落 | 按现有表 | 不变（僵尸数量 ×1.5，总收入约 ×1.5） |
| 续弹 | `cost × ammo` | 不变，从共享池扣 |
| 护盾充能 | 不变 | 不变，从共享池扣 |

豌豆仍然免费（承重墙，别动）。双人下特殊武器更珍贵，池子更紧，但不会死锁。

**武器槽完全独立**：两人各有一套 1~5 号槽与弹匣，互不影响；共享的只有阳光池。客人的续弹请求发送给房主，由房主校验冷却与池子余额后再扣。

**补给请求**：按 V 在准星处打一个标记，队友屏幕边缘出现方向箭头 + "队友请求支援"。倒地时每 5 秒自动打一次。只有一种标记，不做轮盘。

### 4.4 Boss 双目标

| 参数 | 值 |
| --- | --- |
| Boss 血量 | 单人 1450 × 波次倍率 × 1.5（双人血量）× **1.33** ≈ 单人的 2.0 倍 |
| 仇恨切换 | 每 **8 s** 换一次目标，切换前 1 s 吼叫 + 红光亮起 |
| 砸地 | 1.0 s 前摇，半径 4 m，两人都在 3 m 内会同时吃伤害 |
| 破绽 | 砸地后木棒卡地 **2.5 s**，背部受击 **×2 伤害** |
| 破绽归属 | 伤害照常按占比计分——谁抢到背身谁拿分 |

换仇 + 破绽给两个人各自一个明确 job：被点名的走位，没被点名的绕背输出。没有这个，双人 Boss 只是"血更厚的木桩"。

## 5. 竞争层（只抢分，不抢命）

### 5.1 伤害占比分账（核心公式）

```
击杀池 = ZOMBIES[type].score × (爆头击杀 ? 1.5 : 1)
个人得分 = 击杀池 × (你对这只僵尸造成的伤害 / 全队伤害)
尾刀奖励 = 击杀池 × 0.15（只给最后一击）
```

- 爆头伤害本身 ×3，所以爆头者天然拿更大占比；不额外再乘一次。
- 没有助攻门槛：摸一下就有份，但份很小。
- **不做"最后一击拿走全部分"**，否则两人会互相留手、等残血，合作直接崩。

### 5.2 悬赏怪（每波 1 只）

- 第 2 波起，每波随机标记 1 只非 Boss 僵尸：金色描边 + 头顶"通缉"标记。
- 击杀者额外 **+300 个人分**（尾刀归属，不按伤害分）。
- 悬赏怪的基础击杀分仍按 §5.1 分账。
- 目的：给"抢"一个高频、低风险、双方都看得见的舞台。

### 5.3 补给争夺（常规先到先得 + 空投竞速）

**常规地面植物**：刷新规则沿用现有——开局 1 个，之后每 4~8 秒在一个没用过的点位补刷，每关每点位只出一次。

- **全队唯一**：两人看到同一件补给；谁先碰到谁拿走，拿走瞬间两边画面同时消失。
- **不加个人分**：常规补给只改变火力，不改变比分，避免"为了刷分抢走自己用不上的枪"。
- 拿不到的人仍有豌豆保底，漏一件不会失去战斗力——这是"抢"不变成"恨"的底线。
- 双方 HUD 都能看到"队友拿到了 XX"，让失去是可见的、可沟通的，而不是黑箱。
- **防滚雪球（可选，默认关闭）**：同一名玩家 60 秒内最多拾取 2 件常规补给，第 3 件对他锁定 10 秒、对另一名玩家正常可拾。实测出现"一个人拿光所有枪"再打开。

**空投**（每 3 波 1 次）：

| 参数 | 值 |
| --- | --- |
| 时机 | 第 3、6、9、12… 波开始后 20 s |
| 落点 | 随机一个当前没被使用的 pickupSpot，落地前 5 s 显示光柱 |
| 内容 | 随机一把"钥匙武器"（机枪 / 西瓜 / 火豌豆 / 仙人掌）+ 40 阳光 + 满弹匣 |
| 归属 | **全队唯一**，先碰到的人拿走 |
| 得分 | 拾取者 +200 个人分 |
| 风险 | 落地期间波次不停，去拿就要离开输出位 |

常规补给是"持续的小争夺"，空投是"每 3 波一次的高光争夺"。两者都只抢火力，不抢命；真正的比分仍由伤害占比、悬赏、救援决定。

### 5.4 个人连杀与胜负

- 每连续击杀 5 只，个人得分倍率 +10%，最高 **×1.5**；倒地或淘汰清零。
- 局末比较**个人总分**，高者胜；平局看击杀数，再平看爆头数。
- 胜者获得下一局"先选地图"权（社会性奖励，不改数值）。
- **再来一局交换房主**（seat 0/1 互换），抵消房主 0 延迟优势；服务器在 rematch 时交换座位。
- 服务器按设备 token 记录：最高波次、最高合计分、两人的交手战绩（W/L）。

### 5.5 反毒性红线

| 规则 | 原因 |
| --- | --- |
| 无友伤 | 竞争不能变成互相伤害 |
| 玩家之间无碰撞 | 不能堵门、不能推人下平台 |
| 分数只加不减 | 失误不该被队友记恨 |
| 常规补给不加分 | 抢枪只影响火力，不产生"抢分"动机；豌豆免费保底 |
| 倒地不扣分，只清连杀 | 惩罚是"少打 30 秒"，不是"被队友骂" |
| 阳光消耗公开 | 让资源使用可复盘，而不是互相猜疑 |
| 不做玩家投票踢人 / 投降 | 2 人局没有多数 |

## 6. 双人难度缩放

```js
// src/config.js
export const DUO = {
  countMul: 1.5,          // 每波僵尸数量 ×1.5
  hpMul: 1.5,             // 僵尸血量 ×1.5
  bossHpMul: 1.33,        // Boss 在 hpMul 之上再乘，合计约单人的 2.0 倍
  spawnIntervalMul: 0.9,  // 刷怪间隔 ×0.9
  maxAlive: 14,           // 同屏上限不变（渲染预算是硬约束）
  airQuotaBonus: 1,       // 气球同屏配额 +1
  startSun: 80,
  maxSun: 400,
  skySunInterval: 22,
  intermission: 5.0,      // 单人 6.5 s
  sunOrbPool: 40,         // 单人池 28；双人击杀密度 ×1.5，避免 Boss 波静默丢球
};
```

**设计意图**：双人总血量 ≈ 单人 ×2.25，总 DPS ≈ ×2，人均压力 ≈ 单人的 1.12 倍。  
同屏上限仍是 14，所以双人不是"更多怪"，而是"更耐打的怪 + 更密的波次"。

> 阳光经济复核：总 HP ×2.25、击杀阳光收入 ×1.5 → 每点伤害的阳光收入是单人的 0.67 倍。豌豆免费不会死锁；如果 M2 实测特殊武器长期买不起，先调 `sunDropMul 1.2`，不要直接降 `hpMul`（那会把人均压力从 1.12 降到 1.0，双人反而变简单）。

### 前 10 波（以雪地图为例，含骷髅）

| 波次 | 僵尸数（×1.5） | 同屏上限 | 刷怪间隔 | 事件 | 张力峰值 |
| --- | --- | --- | --- | --- | --- |
| 1 | 8 | 8 | 1.17 s | — | 25 |
| 2 | 11 | 9 | 1.12 s | 悬赏 | 40 |
| 3 | 17 | 9 | 1.07 s | 悬赏 + 空投 | 55 |
| 4 | 23 | 10 | 1.02 s | 悬赏 | 65 |
| 5 | 30 | 10 | 0.97 s | **Boss** + 悬赏 | 85 |
| 6 | 38 | 11 | 0.92 s | 悬赏 + 空投 | 35（休整后回踩） |
| 7 | 44 | 11 | 0.87 s | 悬赏 | 55 |
| 8 | 51 | 12 | 0.82 s | 双线突袭 + 悬赏 | 70 |
| 9 | 60 | 12 | 0.77 s | 悬赏 + 空投 | 80 |
| 10 | 66 | 13 | 0.72 s | **Boss** + 悬赏 | 95 |

- 清波休整 5 s，张力回落到 20；每 3 波的空投把休整拉长到 10 s（但空投本身是竞争）。
- 严禁连续 3 波 ≥70：第 4~5 波连续高压后，第 6 波必须回踩。
- 第 8 波"双线突袭"：僵尸从两个相对方向同时进场（雪地北基地 + 东侧通道），逼两人分头或快速轮转。

## 7. 空间与仇恨

### 7.1 双出生点

每张地图新增 `spawns`，两名玩家相距 3~4 米、朝向一致：

| 地图 | P1 | P2 |
| --- | --- | --- |
| 后院 | (0, 13) | (3, 13) |
| 雪地 | (0, 19.2) | (-3.5, 19.2) |
| 沙城 | (0, 20.5) | (3.5, 20.5) |

### 7.2 仇恨分配

- 每只僵尸默认追**最近**的玩家；每 **2 s** 重新评估一次，并有 25% 概率随机换目标，避免所有怪像磁铁一样贴同一个人。
- 倒地者 2.5 s 后失去仇恨（僵尸转向站着的人）。
- Boss 每 8 s 强制换目标，带 1 s 预警。
- 刷怪点与两名玩家的距离都要 >14 m（现有规则从"避开玩家"改为"避开两人"）。

### 7.3 寻路

雪地与沙城用 1 米网格流场。双人需要**两张流场**（每人一张），每张 4 Hz 更新；两张网格的内存与 BFS 开销都可以忽略（最大 53×53 ≈ 2.8k 格）。僵尸按当前仇恨目标选流场。

## 8. HUD 与流程

### 8.1 对局 HUD 新增

| 位置 | 内容 |
| --- | --- |
| 顶部中央（波次下方） | `你 1,240 : 980 队友` 对决条，领先者戴小王冠 |
| 左上 | 自己 HP / 护盾（现有） + 个人分数（现有积分改为个人分） |
| 左下 | 队友卡：名字、HP 条、护盾、倒地倒计时、延迟、专精图标 |
| 世界内 | 队友头顶名牌 + 血环；屏幕边缘离屏箭头（距离 <8 m 时显示） |
| 准星下方 | 救援提示"按住 E 救起 XX（2.5s）"+ 环形进度 |
| 阳光胶囊 | 共享池数字 + 一条双色贡献条（谁捡的更多） |
| 左下（队友卡上方） | 补给播报："队友拿到了机枪" / "空投已落地" |
| 右上 | 延迟 / 掉线提示 |

触屏：右下开火区上方新增"救援"按钮（仅在 3 m 内出现），其余沿用现有布局。

### 8.2 流程

```
主菜单
 ├─ 单人（完全离线，不连服务器）
 └─ 双人
     ├─ 连接中 → 失败（可重试）
     ├─ 自动配对：有人等待 → 直接加入；没人等待 → 新建一场并等待
     ├─ 等待队友（1 号位可改地图；显示"把网址发给朋友"；10 分钟无人来可重新匹配）
     ├─ 队友加入 → 3-2-1 倒计时 → 开始
     ├─ 对局中（任一方可暂停；切后台 >10s 自动暂停）
     ├─ 队友掉线 → 冻结 + 45 s 重连窗口
     └─ 结算 → 双方都点"再来一局" → 同一对局内换种子 + 交换房主重开（不用重新匹配）
```

- **暂停规则**：双人下 Esc 只释放鼠标、不暂停（否则队友会被"锁鼠标"绑架）；点暂停按钮或 `visibilitychange` 立即暂停并中继给队友，任一方可恢复，120 s 自动恢复。
- **离开**：任一方主动退出 → 对局立即结束，另一方看到结算与"队友已离开"，可重新匹配。
- **重连**：45 s 内带 token 回来可回到原座位；超时对局结束。**网络抖动（pageId 不变）**回原座位；**页面刷新（pageId 变）**时房主刷新 = 本局结束（客人收到 `HOST_RESET`），客人刷新 = 回座位但 M1 世界重置，M2 发 `resync`。
- **再来一局**：双方都点才重开（同一对局内换种子 + 交换房主）；只有一人点，30 秒后该玩家回到自动配对。
- **等待超时 / 满员**：10 分钟无人加入 → 提示"重新匹配"；并发上限满 → 返回 `busy`，客户端 10 秒后自动重试。
- **邀请链接**：房主等待时地址栏自动带 `?join=<12 位>`，点「复制邀请链接」发给朋友；朋友打开即加入该场。自动配对是兜底（没有 join，或 join 失效后清掉参数重新匹配）。

## 9. 技术架构

### 9.1 权威划分（推荐：房主权威 + 服务器记账）

```
     ┌─────────────┐        WebSocket        ┌─────────────┐
     │  P1 浏览器   │◄───────────────────────►│  Node 服务  │
     │  （房主）    │   配对 / 中继 / 记账     │  （多场并列）│
     │  僵尸模拟    │                         └──────┬──────┘
     │  伤害裁决    │                                │ 中继
     └──────┬──────┘                                │
            │ 快照 20Hz / 输入 30Hz（M2）            │
     ┌──────▼──────┐◄───────────────────────────────┘
     │  P2 浏览器   │
     │  只渲染+预测 │
     └─────────────┘
```

**为什么不做服务端全量模拟**：现有地图、僵尸、粒子全是 Three.js 场景对象，服务端跑需要把渲染与模拟彻底拆开（Zombie → ZombieSim + ZombieView），是一次伤筋动骨的重构。2 个朋友玩，作弊不是主要威胁。

**代价**：房主有 0 延迟优势，客人的命中要等一个 RTT。对 PvE 僵尸影响可接受；如果以后比分 duel 变得认真，再升级成"两人各模拟一半僵尸"（按 id 奇偶分权），延迟就对称了。

**服务器职责**（不模拟，只裁决）：
1. **自动配对**：维护等待队列与多场并发（见 §9.1.1），每场 2 个座位。
2. 中继所有消息（不解析游戏内容）。
3. 接收房主上报的记分/结算，做合理性审计（每秒得分上限、击杀速率、阳光收支），落盘 JSONL。
4. 提供 `/api/health`、`/api/stats`（排行榜）、管理员 `/api/reset`（带 token）。

#### 9.1.1 自动配对（多场并发）

服务端维护两个集合：`waiting`（FIFO，只有 1 人的场）与 `matches`（全部场），以及 `byJoin`（joinToken → 等待中的场）。

```text
on hello(token, page, join, build):
  token 命中已有座位:
    page 与座位一致       → 网络重连，回原场
    房主 page 不一致       → 结束旧局，房主新开一场（客人收到 HOST_RESET）
    客人 page 不一致       → 回原座位（M1 世界重置；M2 发 resync）
  join 命中等待中的场     → 加入该场（邀请链接优先于 FIFO）
  join 未命中             → JOIN_EXPIRED（不静默改成随机匹配）
  waiting 中有同 build 的场 → FIFO 兜底
  否则                     → 新建一场，占 1 号位，返回 joinToken
```

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `MAX_MATCHES` | 8 | 同时最多 8 场（16 人）；满了返回 `busy` |
| `WAIT_TTL` | 10 min | 等待超时销毁该场，客户端提示"重新匹配" |
| 空场回收 | 连接断开即回收 | 没有重连 token 的等待者直接销毁 |
| 重连窗口 | 45 s | 断线期间保留座位；超时对局结束 |
| 邀请链接 | 12 位 `joinToken` | 房主等待时生成，写进 `?join=`；开局即失效。不是手动房间 |
| `MAX_CONN_PER_IP` | 6 | 同一 IP 的连接上限；Caddy 后要设 `TRUST_PROXY=1` 读 `X-Forwarded-For` |
| `TRUST_PROXY` | 关 | 反代部署时打开，否则所有连接看起来都来自 127.0.0.1 |
| 房间码 / 密码 | 无 | 只有全服可选的 `ACCESS_CODE`，不是房间 |
| 带宽估算 | ~40 KB/s/场 | 8 场约 320 KB/s，中继压力可忽略 |

- 这里的"场"是服务端内部的对局实例，不是玩家手动建的房间；玩家侧仍然只有"双人"一个按钮。
- 同一 token 不能同时占两个座位；重复连接踢掉旧连接。
- 单人模式不建立任何连接，网络模块用动态 `import()` 懒加载，不增加单人首屏体积。

### 9.2 同步参数

| 项 | 值 | 理由 |
| --- | --- | --- |
| 房主模拟 | rAF + 可变 dt | 只有房主一个模拟器，不需要固定步长/回放；固定 30 Hz 反而量化房主视角 |
| 快照频率 | 20 Hz | 14 只 ≈ 1.1–1.3 KB/帧，约 20–26 KB/s；预算按 25 KB/s |
| 输入频率 | 30 Hz（已实现） | guest 发 `input {m,look,jump,fire,shield}`；host 跑 guest 代理并 20 Hz 回 `pstate` |
| 客人插值 | 100 ms @ 20 Hz | 两帧快照之间插值；4G 抖动大时实验 A 后再到 150 ms |
| 最大外推 | 1–2 s | 120 ms 对 GC/切后台太敏感 |
| 位置校正 | 0.2 m / 0.15 s | 或输入重放；0.4 m 在 20 Hz 下几乎不触发 |
| 回退 | 按 `snap.seq`，最多 250 ms | 30 Hz × 0.25 s ≈ 8 帧/僵尸，14 只约 4 KB；不用墙钟 |
| 心跳 | 2 s | 只测 RTT；时钟域用 seq，不用心跳做时钟同步 |

**快照 schema（v1.1）**：

```text
snap { seq, t, wave, waveState, sun, bossHp, bountyId, dropId,
       z:[{ id,t,x,y,z,yaw,hp,st,at }],
       p:[{ s,x,y,z,yaw,pitch,hp,down,sc,w,a,sh }] }
```

- `y` 不能省：气球 `airHeight 2.2`、玩家跳上矮墙/箱子都靠它。
- `w/a/sh` = 武器 index / 弹匣 / 盾血（0 = 未举起）；房主校验命中和模拟客人承伤都需要。
- `st/at` = 动画状态 / 攻击计时；客人用它对动画。
- **spawn/despawn 走 `evt`**，不要靠"快照里有没有这只"推断，丢一帧会把僵尸删了又建。

**命中流程（M2）**：

```text
hit { zid, seq, weapon, dir:[x,y,z] }
```

房主五步：
1. 按 `seq` 取自己保存的客人相机（位置 + yaw/pitch，300 ms 环形缓冲），**不信客人传的 origin**。
2. `dir` 必须落在该武器的 spread 锥内，且与相机前向夹角 ≤ 武器锥角。
3. 按 `WEAPONS[weapon].damage` × 部位倍率重算伤害与爆头，`dmg/head` 不再从客人读。
4. 校验冷却、弹匣、射程、`HitWalls.sweepWalls` 遮挡。
5. 回 `hitAck {seq}` 或 `reject {seq, reason}`；客人回滚本地命中标记。

客人本地 `Zombie.hit()` 必须走 **flashOnly**：只白闪，不扣血、不触发 `ZombieManager.handleKill`、不掉阳光、不加分。

**阳光 / 补给（M2）**：客人 `spendSun` 不能保持同步 bool。走 `sunAck/sunReject`（客人预测扣款、拒绝回滚），或房主按波给客人一个预授权额度。拾取仍由房主裁决，`claim` 带 `seq`。

**客人权威分支（僵尸部分已落地）**：guest 跳过 `map.updateNav`、`skySun`、`sunOrbs`、`pickups` 的权威结算；`zombies.update` 走远端分支，只消费 host 的 `zspawn` / `zdead` 事件和 20 Hz `pstate.z` 快照（`Zombie.applyNetState`）。host 保留完整模拟，`Zombie.serialize()` 发 `id/type/x/y/z/yaw/hp/st/sl`。客人侧本地 `Zombie.hit()` 只白闪，不扣血、不 `handleKill`、不掉阳光。房主的客人 `Player` 是无副作用代理（`sfx=null`、`onDamage/onDeath=null`）。**仍未做**：共享补给 claim、阳光球同步/claim、`WallNuts` 每玩家一份、guest `resync`、双人缩放。

### 9.3 协议（JSON v1，够用再换二进制）

| 方向 | 消息 | 内容 |
| --- | --- | --- |
| C→S | `hello {token, page, join?, name, build, mapId, access?}` | 入场；page 区分刷新，join 是邀请链接 |
| S→C | `welcome {matchId, seat, host, state, mapId, seed, t0, peer, token, joinToken?}` | 座位与开局参数；joinToken 仅等待中的房主 |
| S→C | `queue {state: waiting/timeout}` | 配对状态 |
| S→C | `peer {joined/left, name, reconnectIn?}` | 队友状态 |
| C→S | `map {id}` / `bye` | 房主选图 / 主动离开 |
| S→C | `start {mapId, seed, t0}` | 开局 |
| C↔S | `relay {payload}` | 盲转发（≤32 KB） |
| Host→Guest | `snap {seq,...}` / `evt {type,...}` / `resync {...}` | 快照 / 事件 / 客人重连完整状态 |
| Host→Guest | `hitAck {seq}` / `reject {seq, reason}` | 命中回执 |
| Guest→Host | `input {seq,m,look,jump,fire,shield}` / `hit {zid,seq,weapon,dir}` / `claim {kind,id,seq}` / `revive {target,seq}` | M2 输入与请求 |
| S→C | `end {reason}` / `error {code}` | 结束 / 错误（JOIN_EXPIRED、BUSY、DUPLICATE、HOST_RESET 等） |

- 房主可以改自己的分数——这是房主权威的固有代价，写进已知限制。

## 13. 已知限制（写进 README，别当 bug）

1. 房主权威：房主掉线 / 切后台会冻结全场；房主理论上可以改分。
2. 自动配对可能匹配到陌生人；没有好友系统 / 房间码，想和指定的人玩只能约好同时点"双人"（或全服共用 `ACCESS_CODE`）。
3. 常规补给全队唯一、先到先得：队友可以先拿走你想要的枪。这是刻意保留的竞争，不是同步 bug；补给不加分、豌豆免费，漏一件不会掉队。
4. 客人命中要等一个 RTT；房主在分数 duel 上有微小优势。
5. 不做 host migration：房主 45 s 不回来，本局结束。
6. 双人同屏上限仍是 14，难度靠血量与密度，不靠堆数量。
7. 服务器并发有上限（默认 8 场），满了返回 `busy`；这是保护机器的硬限制。
8. 没有语音、没有文字聊天，只有一种标记。
9. 队友是 Quaternius Farmer 的戴夫化版本，不是 EA 的 Crazy Dave；锅盖帽/胡子/枪是程序化补件，单只约 12 个蒙皮 draw call。
10. （已过期，保留作记录）M1 时代只同步玩家的位置/朝向/移动/开火。M2 之后僵尸、命中、共享阳光值、个人分、倒地救援都已接。
11. M2 的 **input + guest 僵尸世界分支已实现**：guest 30 Hz 发 `input`，host 跑 guest 代理并 20 Hz 回 `pstate`（含 `z` 快照、wave、bossHp）与 `zspawn/zdead` 事件；guest 只 `applyNetState`，跳过 skySun/sunOrbs/pickups/流场，本地命中只白闪。**命中裁决已接（还缺相机历史与弹匣校验）；共享补给 claim、host 双目标仇恨还没做**。
12. M1 远端用 100 ms 平滑，不是快照缓冲：移动中约 100 ms 视觉延迟，静态位置一致。
13. 客人刷新在 M1 会重置本地世界；M2 必须发 `resync`（武器/弹匣/盾/波次/阳光/僵尸/补给）。
14. 命中裁决（射线/伤害/爆头/冷却/遮挡）已接；共享阳光的跨端扣款是 guest 本地预测 + `sun` 请求，缺 host 侧余额校验与回滚；补给的跨端 claim 仍没有。
15. 倒地救援已实现（靠近自动救起）；双人 Boss 换仇、悬赏、协同、空投、结算页、再来一局仍是 M3。
16. M1 队友掉线时只冻结远端并弹横幅，本地游戏继续；M2 有僵尸后必须全局限时冻结（评审 P1-5）。
17. host 的僵尸已经会追最近的两名玩家；但 guest 代理的 `WallNuts` 只同步了移速开关，盾血/吸收还没按玩家独立结算。
18. 双人波次仍用单人 `wavePlan`（数量/血量/Boss 不乘 1.5/2.0）；`DUO` 配置还没接，难度比设计稿低。
19. 常规补给是**每客户端本地掉落**，不是“全队唯一、先到先得”；共享 claim 未做。
20. 阳光球仍是 host-only：guest 用 pstate 的共享阳光值，但看不到、也不能捡地上的球。
21. 倒地救援是“队友靠近 2.5 秒自动救起”，不是按住 E；触屏没有救援按钮。
22. 结算只是菜单上的一行比分；没有独立结算页/再来一局；guest 刷新没有 `resync`。
23. guest 命中裁决有射线/头身/墙体/冷却/seq 快照回退，但还没有相机历史与弹匣校验；guest 仍自报武器 id。
